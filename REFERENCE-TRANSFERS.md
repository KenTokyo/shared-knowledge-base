# Repository and reference transfers

Read only when the user requests adoption of an existing mechanism, asset system or reference result. [Coding Rules](CODING-RULES.md) owns permissions, checks and task planning.

## Trace before editing

- Pin the source commit and public trigger. Trace source and target: trigger → data/state → algorithm → rendering/UI → reset/cleanup. Inspect directly coupled dependencies and competing legacy paths.
- Record the requested quality-bearing properties: behavior, interaction, timing, material/asset logic, data flow, lifecycle and visible result. Matching names, colors or a few parameters is not enough.
- Map every production slot. Decide which coupled pieces to keep, adapt, repair, replace or remove after checking references.

## Integrate the real path

- Adopt the complete runtime slice that produces the requested quality. Use one adapter for IDs, coordinates, a shared clock and native render contracts where necessary.
- Route real product triggers through the implementation. Delete displaced paths after confirming no production references remain; do not ship a parallel demo, overlay, permanent fallback or duplicate state/render owner.
- A different target architecture is acceptable when it supports the same required behavior. Replace incompatible foundations coherently; line-count minimization is not the goal. Protect unrelated working behavior.
- Verify source content, finite values, expiry and reset across all slots. A pilot is not completion when the request covers the full feature.

## Diagnose repeated mismatches

- Treat the previous approach as disproven for the repeated defect. Reopen source and target; find the first causal difference rather than repeating brightness, scale or color tuning.
- Check events/beats, distance, coordinate/time references, layers, uniforms, blend/depth, light, HDR/post-processing, materials/assets and lifecycle. Repair coupled architecture where it blocks the result.
- When browser inspection is authorized, compare source/target at the same product beat with comparable relative image size, camera distance and render path, within the central runtime budget.
- Without permission, use static evidence and directly supplied reference images. Give a precise manual acceptance path; never claim runtime visual equality from a build alone.
